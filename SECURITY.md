# Security Policy

## Supported Versions

Repositories in the `scimsandbox` organization support the latest code on the `main` branch and the latest container images or artifacts published from `main`.

## Reporting a Vulnerability

Please **do not** open public GitHub issues for security vulnerabilities.

Use GitHub Private Vulnerability Reporting where enabled:

1. Open the affected repository's **Security** tab.
2. Select **Advisories** → **Report a vulnerability**.
3. Include the affected component or endpoint, reproduction steps, security impact, and any suggested fix.

If GitHub Private Vulnerability Reporting is unavailable on a specific repository (for example, on a private or non-code repository), contact the maintainer privately via the contact channels listed on the [`scimsandbox` GitHub profile](https://github.com/scimsandbox) or [@edipal](https://github.com/edipal) rather than opening a public issue.

> [!WARNING]
> **Sandbox Environment Notice:** SCIM Sandbox services are designed for testing and compliance validation. Request and response payloads may be stored without redaction for debugging purposes—review each repository's `SECURITY.md` before deploying outside isolated sandbox environments.
